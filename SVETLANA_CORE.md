# Одна Светлана для всех сайтов

Модель, характер и знания живут в одном месте: в backend «Мира Самозанятых»
(`backend/src/ai/sites.js`, маршрут `/api/v1/assistant`). Сайты не ходят в модель
сами, а спрашивают Светлану через этот сервер. У каждого сайта свой профиль темы.

| Сайт | Профиль | Что может |
|---|---|---|
| Мир Самозанятых | `mir` | работа самозанятого на платформе: заказы, CRM, документы, НПД, гранты |
| АИКО маркетплейс (Svetlana-App) | `aiko` | товары и услуги АИКО, заказы, доставка, кабинет продавца |
| Я-Зарядка AI | `zaryadka` | говорит как Пико: зарядка, привычки, учёба по шагам, рисование; детский режим |
| Светлана Репетитор | `repetitor` | вся школьная программа 1–11 класса, ВПР, ОГЭ/ЕГЭ, IELTS/TOEFL, помощь учителю; без готовых решений и ГДЗ |
| Svetlana 2.0 (Windows) | `svetlana2` | полный режим: писать код, управлять командой, вести все проекты |

Код и управление командой есть только в `svetlana2`. Остальные профили жёстко
держат тему и не отправляют на сторонние сайты: инструкция плюс фильтр ответа.

## Как подключить сайт

1. Придумать длинный случайный ключ (32+ символа) для сайта.
2. На сервере Светланы добавить переменную `ASSISTANT_KEY_<САЙТ>`
   (`ASSISTANT_KEY_MIR`, `ASSISTANT_KEY_AIKO`, `ASSISTANT_KEY_ZARYADKA`,
   `ASSISTANT_KEY_REPETITOR`, `ASSISTANT_KEY_SVETLANA2`).
3. На сервере сайта (Vercel или VPS) положить тот же ключ и адрес Светланы.
   В браузер ключ не попадает.
4. Запрос с сервера сайта:

```
POST https://<сервер Светланы>/api/v1/assistant/<сайт>/chat
Authorization: Bearer <ключ сайта>
{ "message": "…", "history": [{ "role": "user", "content": "…" }] }
→ { "site": "<сайт>", "content": "…" }
```

Нет ключа в окружении — профиль выключен (503), а не открыт для всех.
Проверка: `GET /api/v1/assistant/sites` показывает, какие профили включены.

Svetlana 2.0 (полный режим) и АИКО могут передать своё поле `system` (инструкции агента, формат,
контекст). Оно добавляется после правил профиля и не отменяет их, фильтр ответа АИКО
работает как обычно. У других сайтов поле игнорируется, из браузера не принимается никогда.
Лимиты запроса с ключом: сообщение до 16 000 символов, до 10 реплик истории по 8 000.

### Svetlana 2.0 (Windows)

Провайдер «★ Светлана Сервер» в разделе «Модели и Провайдеры ИИ» → облачные. Ключ —
`ASSISTANT_KEY_SVETLANA2` с сервера (`grep ASSISTANT_KEY_SVETLANA2 /etc/svetlana/backend.env`).
Ключ хранится в Диспетчере учётных данных Windows, запрос делает нативная часть приложения
только на `https://мир-самозанятых.рф/api/v1/assistant/svetlana2/chat`, каждый новый разговор
подтверждается в окне Windows.

### АИКО (Svetlana-App, Vercel)

В настройках проекта АИКО на Vercel (Settings → Environment Variables) добавить:

- `SVETLANA_CORE_URL` = `https://мир-самозанятых.рф` (только https);
- `SVETLANA_CORE_KEY` = значение `ASSISTANT_KEY_AIKO` с сервера
  (`grep ASSISTANT_KEY_AIKO /etc/svetlana/backend.env`).

После пересборки текстовые задачи агентов АИКО идут в единую Светлану. Задачи с инструментами
(tool calling) и эмбеддинги пока остаются на внешнем провайдере АИКО. Нет переменных
или сервер недоступен — АИКО работает как раньше.

## Сайт без своего сервера (вызов из браузера)

Для статических сайтов (Репетитор на Vercel, веб-версия АИКО) ключ в браузере держать нельзя,
поэтому есть отдельный вход без ключа:

```
GET  https://<сервер Светланы>/api/v1/assistant/public/<сайт>/chat  → { "ok": true, "configured": true|false }
POST https://<сервер Светланы>/api/v1/assistant/public/<сайт>/chat
{ "message": "…", "history": [ … до 6 реплик ] }
→ { "site": "<сайт>", "content": "…" }
```

- Включается переменной `ASSISTANT_PUBLIC` (через запятую): `ASSISTANT_PUBLIC=repetitor`.
  Разрешены только профили с `publicOk` (сейчас `repetitor` и `aiko`). `svetlana2` и `mir` из браузера недоступны никогда.
- Адрес сайта должен быть в `CORS_ORIGINS`, иначе браузер не пустит запрос.
- Лимит 20 запросов в минуту с одного IP. Телефоны и e-mail скрываются до отправки в модель.
- Системный промпт задаёт сервер (профиль сайта); браузер его не передаёт и не может заменить.

Репетитор: профиль `repetitor` на сервере готов. Клиентская часть в репозитории Репетитора
подключается отдельно, когда закончится его текущая доработка.
